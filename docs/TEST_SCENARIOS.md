# Тестовые сценарии

Предусловия: весь Compose здоров, каталог загружен, используются только данные из [demo](../demo/README.md). Статусы ниже — ожидаемые результаты, а не утверждение о выполнении теста. Фактический журнал проверки находится в [COMPLIANCE.md](COMPLIANCE.md).

| ID | Действия | Ожидаемый результат |
|---|---|---|
| E2E-01 | Регистрация demo_approved, профиль, каталог, 3 млн на 3 года | 201 регистрации; правильный профиль; заявка ACCEPTED и видна в истории |
| E2E-02 | demo_counter_term: 3 млн на 2 года, принять предложение | COUNTER_OFFER на 4 года, затем ACCEPTED; неизменённые поля берутся из исходной заявки |
| E2E-03 | demo_counter_amount: 3 млн на 3 года, отклонить предложение | предложение 1 510 000 на 5 лет, затем REJECTED |
| E2E-04 | demo_rejected: 1 млн на 3 года без залога | REJECTED с объяснением причины |
| E2E-05 | demo_manual: 3 млн на 3 года с залогом; /resolve APPROVED | UNDER_CONSIDERATION, очередь PENDING, затем callback DELIVERED и ACCEPTED |
| API-01 | GET заявок без access-токена | 401 |
| API-02 | Под своим токеном запросить заявку другого клиента | 404, чужие данные не раскрыты |
| API-03 | Подать сумму/срок вне лимитов продукта | 400; UI также объясняет лимит |
| API-04 | organizationType отличается от аккаунта | 400 |
| API-05 | Повторно ответить на обработанное встречное предложение | 409 |
| API-06 | /api/v1/decisions без сервисного токена | 403 |
| API-07 | Повторить запрос скоринга с тем же applicationId и содержимым; затем изменить тело | прежнее решение; для изменённого тела 409 |
| API-08 | /auth/refresh, затем использовать отозванный refresh | новая пара токенов; старый токен отклонён |
| DATA-01 | Выйти, обновить вкладку, войти снова | профиль и история сохранены; токены в браузере после reload отсутствуют |
| DATA-02 | docker compose down, затем up | пользователи/заявки сохранены; очередь decision_service очищена (известное ограничение) |
| FAIL-01 | Остановить decision-service и подать новую заявку | заявка остаётся UNDER_CONSIDERATION; автоматического повторного скоринга нет |
| UI-01 | Недоступен каталог/сервис пользователей | явная ошибка, нет подставных данных или демовхода |

FAIL-01 выполняйте после обычной демонстрации; восстановление контейнера не запускает повторную обработку уже зависшей заявки. Не повторяйте POST заявки автоматически после timeout — сначала проверьте историю.

## Автоматические проверки

- `cd frontend && npm test` — API-адаптер и калькулятор, Node.js 22+.
- `cd backend/decision_service && python -m pytest tests` — правила, фиксированные клиенты, контракт, ручное решение и callback в фейковый сервис; предварительно установить requirements-dev.txt в Python 3.11.
- `cd backend/user_server && sh ./mvnw -Dtest=ProfileAccessTests test` — доступ к собственному профилю без БД.
- Spring `ApplicationTests` требуют соответствующие PostgreSQL. Это не полный набор интеграционных тестов.
- `docker compose config --quiet` проверяет конфигурацию; `docker compose up --build -d --wait` проверяет сборку/готовность, а не все сценарии UI.

Коллекцию [Postman](requests.postman_collection.json) можно использовать вручную; она сохраняет accessToken, refreshToken, productId и applicationId в переменные. Ручное решение и counter-offer запускаются только для подходящего состояния. Перед повторным прогоном переключите логин/ИНН либо используйте вход вместо повторной регистрации.
