# decision_service

FastAPI-сервис принятия решения, совместимый с `application_server`.

- `POST /api/v1/decisions` — принимает существующий Java `DecisionRequest`, возвращает `APPROVED`, `COUNTER_OFFER`, `REJECTED` (HTTP 200) или `PENDING` (HTTP 202, ручная проверка) плюс score / risk grade / ставку / платёж / DTI / рентабельность.
- Недостающие для текущего backend данные (обороты, расходы, платежи по кредитам, БКИ, оценка залога) приходят из детерминированных локальных моков (`deterministic_external_mocks`) — это точка замены на реальные или отдельные mock-сервисы.
- `GET /api/v1/decisions?status=PENDING` — очередь ручной проверки.
- `GET /api/v1/decisions/{decisionId}` — решение, рекомендация модели, статус callback'а.
- `POST /api/v1/decisions/{decisionId}/resolve` — решение сотрудника по заявке на ручной проверке; итог уходит в `application_server` callback'ом.
- `GET /health` — healthcheck.

Все `/api/v1/*` требуют заголовок `X-Service-Token` (в Swagger — кнопка Authorize). Ошибки возвращаются в формате `{message, dateTime}`, некорректные данные дают `400`.

## Правила решения

1. **Стоп-факторы** (балл не считается, метрики ставки и платежа = `null`):
   - убыток или платежи по текущим кредитам больше прибыли;
   - плохая кредитная история без залога, покрывающего сумму кредита;
   - плохая кредитная история у молодого бизнеса (ИП < 3 мес / ООО < 9 мес).
2. **Балльная карта**: база 30 + возраст бизнеса + кредитная история + отрасль по ОКВЭД + рентабельность. Залог в баллы не входит: он снижает потери банка при дефолте, а не вероятность дефолта.
3. **Рейтинг** A / B / C / D (балл ≥ 85 / 65 / 45 / 30) задаёт предельный DTI 0,60 / 0,50 / 0,40 / 0,30. Балл ниже 30 — отказ. Ставку рейтинг не меняет: платёж и DTI считаются по ставке заявки (`loan.rate`: ставка продукта или калькулятора).
4. **Встречное предложение** считается в целых годах, потому что `application_server` хранит срок в годах:
   - сначала та же сумма на более длинный срок: до 5 лет, но не короче запрошенного и не дольше `product.maxDurationYear`; молодому бизнесу — до 1 года;
   - затем меньшая сумма на максимальный допустимый срок, в пределах `product.minSum`–`product.maxSum`; если она меньше `minSum` (или 50 000 руб. без продукта) — отказ.
   - В `counterOffer` заполнены только изменённые поля, остальные `null` («без изменений» по контракту).
5. **Ручная проверка**: рейтинг D или сумма свыше 30 млн руб. Клиент получает `PENDING`, сотрудник видит рекомендацию модели и принимает решение через `/resolve`.
6. Сумма или срок вне лимитов переданного продукта — `400`.

Параметры политики — константы в начале `main.py`: `MAX_EXTENSION_YEARS`, `YOUNG_MAX_TERM_YEARS`, `MIN_LOAN_AMOUNT`, `MANUAL_REVIEW_GRADES`, `MANUAL_REVIEW_AMOUNT`.

## Моки

Для произвольного ИНН профиль генерируется из хэша ИНН, поэтому один и тот же клиент всегда получает одни и те же данные:

| Показатель | Диапазон |
|------------|----------|
| Выручка | 0,5–10 млн руб./мес |
| Маржа по чистой прибыли | от −2% до 28% (около 7% компаний убыточны) |
| Платежи по текущим кредитам | 0–40% прибыли |
| Кредитная история | хорошая 65%, нет 22%, плохая 13% |
| Оценка залога (если отмечен) | 1–30 млн руб., не зависит от суммы кредита |

На заявках к продукту «Потребительский кредит» и через калькулятор это даёт примерно 45% одобрений, 38% встречных предложений, 16% отказов и 1% ручной проверки.

## Тестовые клиенты для демонстрации

Зарегистрируйте пользователя с указанным ИНН, типом `OOO`, ОКВЭД `62.01` и датой регистрации `2019-03-01`, затем подайте заявку на «Потребительский кредит» (12,5%, 50 000–3 000 000 руб., 1–5 лет):

| ИНН | Профиль | Заявка | Исход |
|-----|---------|--------|-------|
| `7700000001` | выручка 4 млн, прибыль 800 тыс./мес, хорошая история | 3 000 000 руб. на 3 года | `APPROVED` |
| `7700000002` | прибыль 200 тыс./мес | 3 000 000 руб. на 2 года | `COUNTER_OFFER`: срок 4 года |
| `7700000003` | прибыль 90 тыс./мес | 3 000 000 руб. на 3 года | `COUNTER_OFFER`: 1 510 000 руб. на 5 лет |
| `7700000004` | плохая кредитная история | 1 000 000 руб. на 3 года, без залога | `REJECTED` |
| `7700000005` | плохая история, залог 10 млн, маржа 7% | 3 000 000 руб. на 3 года, **с залогом** | `PENDING` (рейтинг D) |

Клиенты 1–4 дают свой исход при любом ОКВЭД и дате регистрации старше 9 месяцев. Клиенту 5 нужен ОКВЭД IT, торговли, производства или услуг: со строительством (41–43) или общепитом (55–56) балл падает ниже 30 и заявка отклоняется.

### Ручная проверка (клиент 7700000005)

1. Подать заявку — в `application_server` она останется в статусе `UNDER_CONSIDERATION`.
2. `GET /api/v1/decisions?status=PENDING` — найти `decisionId` (`score-<applicationId>`) и посмотреть `recommendation` и `manualReviewReason`.
3. `POST /api/v1/decisions/{decisionId}/resolve` с телом `{"outcome": "COUNTER_OFFER"}` (условия берутся из рекомендации), `{"outcome": "APPROVED"}` или `{"outcome": "REJECTED", "comment": "..."}`.
4. Сервис отправит callback в `application_server` (до 5 попыток с паузами 1, 2, 4, 8 с); результат — в поле `callbackStatus` решения. Статус заявки сменится на итоговый.

Решения хранятся в памяти процесса: после перезапуска сервиса очередь ручной проверки и история решений пустые.

## Запуск

```bash
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8090 --reload
```

Тесты (правила скоринга, тестовые клиенты, контракт API, ручная проверка с callback'ом в фейковый `application_server`):

```bash
pip install -r requirements-dev.txt
pytest tests
```

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `INTERNAL_SERVICE_TOKEN` | `change-me-internal-token` | межсервисный токен, общий с `application_server` |
| `APPLICATION_SERVICE_URL` | `http://localhost:8083` | куда отправлять callback решения после ручной проверки |
