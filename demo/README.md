# Синтетические демонстрационные данные

`products.sql` создаёт каталог в новой БД Compose. `clients.json` содержит тела регистрации и параметры заявок. Это придуманные данные для тестов, не сведения реальных клиентов и не предложение банка. ИНН используются как ключи моков и не проверяются по контрольной сумме или реестрам.

Пользователи **не создаются автоматически**. Зарегистрируйте клиента в UI или отправьте поле `registration` из JSON на `POST /api/v0/auth/register`. После первого создания входите с сохранёнными логином и паролем: повторная регистрация того же ИНН/ОГРН не допускается. Все тестовые пароли: `DemoOnly2026!`.

Общие параметры: ООО (`OOO`), ОКВЭД `62.01`, дата регистрации `2019-03-01`, продукт «Потребительский кредит», ставка 12,5%. `productId` получите из `/products`, не предполагайте, что он всегда равен 1.

| Логин | ИНН | Сумма / срок / залог | Ожидаемый статус заявки |
|---|---|---|---|
| demo_approved | 7700000001 | 3 млн / 3 года / нет | ACCEPTED |
| demo_counter_term | 7700000002 | 3 млн / 2 года / нет | COUNTER_OFFER: 4 года |
| demo_counter_amount | 7700000003 | 3 млн / 3 года / нет | COUNTER_OFFER: 1 510 000 руб., 5 лет |
| demo_rejected | 7700000004 | 1 млн / 3 года / нет | REJECTED |
| demo_manual | 7700000005 | 3 млн / 3 года / есть | UNDER_CONSIDERATION; у скоринга PENDING |

Финансовые показатели и история заданы в `deterministic_external_mocks` в main.py; произвольные ИНН дают детерминированный профиль из хэша. При изменении продукта, параметров или правил ожидаемые исходы необходимо пересмотреть.

## Ручная проверка

1. Подать заявку demo_manual через кабинет.
2. Открыть `http://localhost:8090/docs`, Authorize — токен `INTERNAL_SERVICE_TOKEN` из конфигурации.
3. Выполнить `GET /api/v1/decisions?status=PENDING`, найти `score-<applicationId>`.
4. Выполнить `POST /api/v1/decisions/{decision_id}/resolve` с `{"outcome":"APPROVED","reviewer":"demo-underwriter"}`.
5. Проверить `callbackStatus=DELIVERED` и обновить статус в кабинете: `ACCEPTED`.

При `FAILED` проверьте application_server и токен. Не перезапускайте decision_service во время демонстрации ручной проверки: его очередь хранится в памяти.
