# Frontend для финального backend

Сохранены стиль главной, иллюстрация, описание сервиса и калькулятор сразу под hero. Подключены реальные API из архива Mephi_alpha-backend_branch 2. Локальных решений и демовхода больше нет.

## Запуск
1. Запустите backend по инструкциям его сервисов: product_server :8081, user_server :8082, application_server :8083, decision_service :8090 и их PostgreSQL.
2. Из frontend: `python3 scripts/dev.py` (Python 3.10+).
3. Откройте http://localhost:8085.

Обычный http.server не подходит: нужен прокси к backend. Адреса upstream можно менять через USER_SERVICE_URL, PRODUCT_SERVICE_URL, APPLICATION_SERVICE_URL, порт frontend — PORT. Без переменных используются адреса выше. Секреты frontend не нужны.

Docker: `docker compose up --build`. Backend запускается отдельно на хосте. Для контейнерной сети измените upstream в nginx.conf. Тесты: Node 22+, `npm test`.

## Проверка сценария
Откройте профиль → Войти / Создать аккаунт. Регистрация включает все поля RegisterRequest. Выберите продукт из каталога, сумму и срок в целых годах. «Подать заявку» открывает подтверждение с целью и залогом. Тип организации берётся из аккаунта (backend запрещает несовпадение). Результат отображает статус и комментарий сервера. Для UNDER_CONSIDERATION есть «Обновить статус»; для COUNTER_OFFER — принятие/отклонение. История — в меню профиля.

Токены только в памяти вкладки; после обновления страницы нужен повторный вход. Refresh выполняется один раз на 401. Пароли не сохраняются. Ошибки backend показываются явно, без подстановки демоданных. POST заявки не повторяется автоматически при сетевой ошибке: сначала проверьте историю.

## Ограничения backend-контракта
Каталог /products не содержит признаков возраста бизнеса, типа организации или залога. Поэтому нельзя честно фильтровать по этим полям — прежние фиктивные переключатели убраны. Залог задаётся в подтверждении заявки. Возраст отображается из registrationDate, а тип организации подтверждается сервером. Скидка не применяется автоматически. Аннуитетный предварительный расчёт показывается только при EQUAL_TOTAL_PARTS; для других способов погашения нужен серверный график.

Исходный backend не изменён. Полный сквозной прогон требует работающих сервисов и БД; в этой среде Docker не найден. Проверены синтаксис frontend и тесты адаптера с ответами по реальным DTO, а не запущенный сервер.
